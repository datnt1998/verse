## Majors

**M1 — `.vbd-scroll` never scrolls: virtualization and scroll-triggered paging are dead.** `app-slowroads.png` ↔ `art-slowroads.png`.
`.vbd-scroll { overflow-y:auto }` sits inside `.vbd-cols { display:grid; grid-template-columns: 252px 1fr; align-items:start }` (`backdrops.css:39-42`). Because the grid item is aligned `start` and not `stretch`, `.vbd-scroll`'s height = content height (measured clientH=2420=scrollH) while its parent `.vbd-cols` is only 663 px; the document element scrolls instead (scrollable: html, 2603/845). `useVirtualGrid` therefore sees `scrollTop=0` and `size.height` unbounded → after "Hiện thêm", **48 DOM cards, padTop/padBottom 0**; the `onScroll → loadMore` auto-fetch can never fire (only the "Hiện thêm" button works). With the 312-video channel this means up to 312 `<article>`s and eventually the whole catalog mounted. Fix: `align-items: stretch` on `.vbd-cols` (or `height:100%`/explicit max on `.vbd-scroll`) so it becomes the scroll box it declares; verify `[data-vrow]` rows then get measured. File: `web/src/screens/library/backdrops/backdrops.css` (`.vbd-cols`).

**M2 — Twitch VOD links are rejected as invalid.** `POST /api/sources/parse {input:"https://www.twitch.tv/videos/2345678901"}` → `{"kind":"invalid", message:"Link chưa đọc được…"}`.
`twitchVodPath = ^/[^/]+/videos/(\d+)/?$` (`internal/backdrop/links.go:47`) only matches `<login>/videos/<id>`; the real Twitch VOD URL is `twitch.tv/videos/<id>` — "videos" is a reserved first segment, not a channel. The add bar hints "Link một video: lưu thành video lẻ", and VOD is exactly the long-video case (10-min segments); a user pasting a VOD gets "invalid link". Fix: accept `^/videos/(\d+)/?$` (and keep the channel-qualified form) in `internal/backdrop/links.go`, so parse → `twitch_vod` → segment strip → video lẻ.

**M3 — `resolveB23` can never see the redirect, and a parse failure can pause the whole platform.**
`POST /api/sources/parse {"https://b23.tv/BV1xx411c7mD"}` → `{kind:"invalid", message:"Không mở được link rút gọn b23.tv"}` while `curl -A '' https://b23.tv/BV1xx411c7mD` returns `301 → bilibili.com/video/BV...` correctly. Two stacked bugs in `internal/backdrop/bilibili_fetch.go`:
1. `pacedDoer.Do` wraps `d.request` into `roundTripDoer` and passes it as `Transport` of a new `http.Client` (lines 25-29) — but `roundTripDoer.RoundTrip` calls `d.base.Do(req)`, an `http.Client` which **follows redirects itself**, violating the RoundTripper contract. `b23Location`'s `CheckRedirect:ErrUseLastResponse` never sees the 301; `Location` ends at bilibili.com's response, `location=""` or a bot-check status.
2. The bilibili.com final response returns 412 for bot-like traffic → `d.base.Do` → `RateLimitError` → `pacer.execute` **sets `platform_state.paused_until=+2h`** (observed: `paused_until 08:35` after one parse, `request_history` consumed 1 slot). So pasting a b23.tv link can never work *and* pauses all Bilibili fetches for hours. Fix: `Location` must use a non-pacing fetch (`s.d.b23Doer` with `CheckRedirect`) or make `roundTripDoer` call `http.DefaultTransport.RoundTrip` (not `client.Do`); treat `Location` failures as `invalid`, never as rate-limited. Files: `internal/backdrop/bilibili_fetch.go`, `internal/backdrop/links.go`.

**M4 — Paused channel renders the "reading" state and hides its 300 videos.**
For `bilibili:3493118` (`listed_at` set, `scan_next_page=5`, `pausedUntil` future): app rail row shows "Đang đọc video…" and the pane shows the "reading" treatment ("Đang đọc…", segment chips hidden). The artboard (`kenh=bilibili`) shows the rail row with ⏰ + "300 video · 1 template", the pause banner *above* a fully populated list: "Video 300", "Đang hiện … / 300". `channelReading(c)` in `ChannelPage.tsx` includes `channel.scanNextPage != null` — a channel parked mid-scan while paused counts as "reading" even though `channels.data` already carries 300 listable rows. The user can't browse or pick the videos that were already read. Fix: treat `paused` as taking precedence — only show reading when `listedAt === null` or `scanNextPage != null && !pausedUntil`; better, let the list render whenever `total > 0` and show "reading" only as a header hint. Files: `ChannelPage.tsx` (`channelReading`), `SourceRail.tsx` (`reading` classification for the rail row).
