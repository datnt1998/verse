## Actionable source-backed findings

### F1 — Desktop template card inherits column direction and loses canonical width limit (S2)

**Evidence:** `Channel.tab.templates.png`, RIGHT: thumbnail at top, all text below, actions below again. LEFT has one compact horizontal row and a visibly narrower template section.

**Cause/owner:** `TemplatesTab.tsx:111` composes `channelStyles.card` and `tplCard`. The base `card` explicitly sets `flexDirection: 'column'` (`channel.stylex.ts:32`); `tplCard` (`:308`) does not override direction. `tplSection` (`:307`) also has no canonical `max-width: 860px`. This is independent of whether artwork exists. Canonical owner `docs/design/v1/artboards/Channel.dc.html:1021` explicitly uses row wrapping/center alignment and section max-width 860px.

**Parent action:** Restore the desktop row composition and canonical width boundary in the owning styles; retain existing mobile composition. Do not solve this by inserting fake artwork.

### F2 — Mobile creation template control overflows its 44px trigger (S2)

**Evidence:** `MCreate.rivals.some.png`, RIGHT around y519–616: value collapses to “Mẫu c…”; wrapped description continues through the row boundary. `MCreate.rivals.empty.png` and `MCreate.step.create.png` show the same text intruding above the run-card title/divider near the bottom crop. Scroll mismatch does not cause this local overflow.

**Cause/owner:** `CreateStep.tsx:461–475` retains desktop-style label plus selector side by side on mobile and passes `inlineDescription`. `mch.tplSelectM` (`mobile/mchannel.stylex.ts:644`) gives the trigger a fixed 44px height and `maxWidth: '60%'`. The description in `responsive-overlays.tsx:52,187–189` wraps normally with `overflowWrap: 'anywhere'`; the fixed-height trigger does not contain that wrapped stack. Canonical `MCreate.dc.html:965–966` uses a full-width row, with template label/value in the same flexible text column, not a second compressed description column.

**Parent action:** Make the mobile template row match that composition; ensure chosen value/description cannot escape its row. Retain the actual value, rather than suppressing content solely to conceal overflow.

### F3 — Generating overlay obscures persistent banner chrome (S2 desktop / S3 mobile)

**Evidence:** Both inspected `*.identity.generating.png` pairs: LEFT banner caption remains visible; RIGHT caption disappears. Desktop LEFT safe-area toggle remains visible; desktop RIGHT toggle disappears. Mobile safe-area row still appears below the overlay on both.

**Cause/owner:** `IdentityBlock.tsx:215–236` renders caption and desktop toggle before the later full-inset opaque `skelOverlay`; `channel.stylex.ts:119,121,149` supplies no stacking separation to keep them above it.

**Parent action:** Preserve the canonical caption and desktop safe-area control above/outside the generation layer. No animation or old-image retention claim is made: the synthetic fixture has no prior art, which is a separate data condition.

### F4 — Mobile unlink confirmation uses desktop dialog body/footer composition (S2)

**Evidence:** `MChannel.sheet.unlink.png`, LEFT actions run approximately x16–191 and x199–374; RIGHT actions occupy a compact group near the right edge instead. RIGHT title/body is narrowed by the warning-icon column and indented list, unlike the canonical mobile sheet.

**Cause/owner:** `SourcesTab.tsx:88–99` unconditionally calls shared `confirm()` with desktop title and bullet-body structure. `ConfirmDialog.tsx:311–327` retains icon/lead columns and a footer spacer with content-width buttons; `:329` merely wraps that content in a responsive Sheet. Footer styles at `:152–154` do not make mobile actions equal-width. The documented kit approval in `docs/design/v1/11-hoi-dap.md:298–302` explicitly addresses **desktop** unlink; it does not establish a mobile visual waiver.

**Parent action:** Match canonical mobile full-width text and equal actions at the channel/mobile confirmation owner without changing the approved desktop confirmation unintentionally. Different source names can remain real data.

### F5 — Rival action-sheet secondary guidance omitted (S3)

**Evidence:** `MChannel.sheet.rival.png`, LEFT includes explanatory text under top-videos and unlink; RIGHT has only single labels. These missing descriptions are not explained by synthetic rival names.

**Cause/owner:** `SourcesTab.tsx:281–284` supplies only labels/icons/actions to `ActionSheet`, including a link icon and no confirmation hint for unlink.

**Parent action:** Restore canonical secondary guidance and icon semantics in this mobile action list. Static evidence establishes visible hierarchy only, not whether confirmation behavior actually fires.
